# Environment Reproduction Status

## Verified boundary

The retained historical project handoff contains Python 3.12 bytecode artifacts and a `pyproject.toml` describing the compatible software families used by the core implementation.

The publication repository therefore separates:

1. **Compatibility specification** — `pyproject.toml`.
2. **Exact reproduction runtime inventory** — generated by `environment/capture_environment.py` on any machine used for a reproduction run.

## Why an exact historical lock is not fabricated

The retained handoff does not contain a complete, trustworthy `pip freeze` or Conda lock for the executed R3–R6 post-review runs. Exact pins are therefore not reconstructed from memory.

If a publication reproduction run is performed, capture its environment as:

```bash
python environment/capture_environment.py --output environment/runtime_inventory_publication.json
python -m pip freeze > environment/requirements-publication-lock.txt
```

Such a lock must be labeled as a **publication reproduction environment**, not as the byte-identical historical execution environment unless that historical lock is independently recovered.

## Installation

```bash
python -m venv .venv
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python environment/capture_environment.py
```

PyTorch Geometric must match the installed PyTorch/CUDA build.

## Public repository note

The absence of a byte-identical historical package lock is documented as a reproducibility limitation rather than silently reconstructed. The public repository therefore provides executable source, compatibility metadata, frozen scientific configurations/results, and a runtime-capture utility.
